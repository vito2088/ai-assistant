# 桌面待办小助手｜产品设计 v0.4

- 日期：2026-10-23
- 状态：当前实现方案
- 上一版：[v0.3](desktop-todo-v0.3.md)
- 本版变化：新增输入框常驻；原“逐条显示”改为紧凑列表

## 1. 目标

待办是桌面小助手的一个功能。用户可以在主界面快速记录事项，也可以将窗口缩为桌面小图标，或切换到紧凑列表，在更小的面积内同时查看多条待办。数据保存在本机。

## 2. 显示状态

| 状态 | 内容 | 尺寸与操作 |
| --- | --- | --- |
| 主界面待办页 | 常驻输入框、添加按钮、完整待办列表 | 430 × 620；可新增、完成、删除、切换紧凑列表 |
| 桌面小图标 | 图标及悬停快捷按钮 | 184 × 184；可展开、新增、固定、打开紧凑列表 |
| 紧凑列表 | 多条待办按行排列，未完成在前、已完成在后 | 360 × 360；可滚动、完成、删除、展开主界面、弹窗新增、收起、最小化 |

主界面和紧凑列表使用相同的单层圆角面板。窗口可以拖动；固定后锁定位置并置于普通应用窗口上方。最小化时保留系统任务栏图标，点击即可恢复；托盘菜单也可显示窗口。

旧版本保存的 `single` 显示状态在启动时迁移为 `compact`，原有待办不变。

## 3. 新增待办

1. 主界面待办页始终显示输入框和“添加”按钮。用户直接输入内容，点一次“添加”或按 Enter 即提交。
2. 从小图标点“新增”会打开主界面并聚焦输入框；紧凑列表底部的“＋ 新增”打开当前窗口内的小弹窗，输入后点一次“添加”或按 Enter 保存。
3. 提交时按钮显示“添加中…”，防止重复提交。数据库写入成功后，新待办立即出现在列表顶部，输入框清空并保持可继续输入。
4. 输入为空或保存失败时，在输入框下方显示错误并保留内容；提示消息的消失不能重建输入框、打断用户输入。
5. 添加、完成和删除都同步到主界面与紧凑列表。重新启动后保持数据。

## 4. 紧凑列表

- 一次显示多条待办，超出窗口高度时在列表内部滚动；不再提供“上一条 / 下一条”。
- 每行显示完成状态和单行标题。长标题省略，鼠标悬停可看全文。
- 每行右侧提供删除按钮，确认后直接删除当前待办并更新列表。
- 点击圆形状态按钮切换完成与未完成；已完成事项显示删除线，并排在未完成事项之后。
- 列表为空时显示空状态和下方新增入口。
- 底部保留“展开主界面”“＋ 新增”“最小化”操作。顶部保留固定与收起按钮。
- 新增弹窗不会改变窗口尺寸或切换到主界面；保存成功后关闭，列表立即更新。输入为空或保存失败时保留弹窗和内容；点击关闭或按 Escape 取消，保留未提交的草稿。

## 5. 验收标准

| 场景 | 预期 |
| --- | --- |
| 在常驻输入框输入内容并点一次“添加” | 数据库增加一条，主列表立即增加一行，输入框清空 |
| 连续添加两条 | 每次只写入一条；最新事项在最上方 |
| 输入为空或保存失败 | 不增加记录，显示错误，不清空已有输入 |
| 从紧凑列表点击“＋ 新增” | 在当前窗口打开小弹窗，光标进入输入框；保存成功后关闭并更新列表 |
| 删除紧凑列表中的一条 | 确认后删除，主界面与数据库同步；仍留在紧凑列表 |
| 切换到紧凑列表 | 同时看到多条待办，过多时可滚动 |
| 完成紧凑列表中的一条 | 状态和顺序更新；主界面显示一致 |
| 重启旧版曾处于逐条模式的应用 | 自动进入紧凑列表，待办数据仍在 |

## 6. 后续迭代

截止日期、提醒、分类、云同步与多端协作不在本版范围。紧凑列表行高可根据使用反馈继续调整。
