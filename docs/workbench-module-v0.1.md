# 工作台模块设计 v0.1

- 日期：2026-10-23
- 状态：本地工作台已开发；账号、同步和跨电脑绑定仍为后续规划
- 适用范围：Windows、macOS、Linux 桌面版
- 相关旧设计：[项目管理 v0.1](project-manager-v0.1.md)、[软件管理 v0.1](software-manager-v0.1.md)

## 1. 命名与层级

主界面调整为 **文档｜工作台｜设置**。“工作台”下先选择一台电脑，再查看这台电脑的 **项目｜应用** 两个子栏目。

| 现有名称 | 建议名称 | 原因 |
| --- | --- | --- |
| 项目 | 项目 | 用户已经知道这里保存项目文件夹和打开方式，暂不需要改名。 |
| 软件 | 应用 | 这里管理常用应用的启动入口，不管理软件的安装和卸载；“应用”更贴近实际操作。 |
| 无 | 工作台 | 作为上级栏目，容纳不同电脑各自的项目与应用入口，也为后续同步留出清晰的归属。 |

工作台中的单个档案称为“电脑”，例如“工作电脑”“家用电脑”。电脑名称可编辑，也可以重名；唯一身份由内部 ID 决定。

```text
小助手
├─ 文档
│  ├─ 待办
│  └─ 速记
├─ 工作台
│  ├─ 工作电脑（当前电脑）
│  │  ├─ 项目
│  │  └─ 应用
│  ├─ 家用电脑
│  │  ├─ 项目
│  │  └─ 应用
│  └─ ＋ 添加电脑
└─ 设置
```

## 2. 工作台首页与操作

```text
┌──────────────────────────────────────────────┐
│ 工作台                       ＋ 添加电脑      │
│ 工作电脑  Windows  ● 当前电脑                 │
│ 家用电脑  macOS    上次使用：昨天             │
├──────────────────────────────────────────────┤
│ 工作电脑   [项目] [应用]                      │
│ 项目：my-assistant        用 VS Code 打开     │
│ 应用：浏览器              打开                │
└──────────────────────────────────────────────┘
```

- 首次使用时创建“当前电脑”档案；升级旧版时自动创建，并将已有项目、软件入口归入该电脑。默认名称可来自系统电脑名，用户可修改。
- “＋ 添加电脑”用于创建另一台电脑的档案。此时状态为“待绑定”，可先填写名称和系统类型；不能填写或启动仅属于另一台电脑的本地路径。当前版本只保存档案，真正绑定要等同步功能加入。
- 在另一台电脑安装并登录未来的同步账号后，可选择“绑定已有电脑档案”或“添加这台电脑”。一个应用安装实例只绑定一个电脑档案；已绑定时“添加电脑”不会再把本机绑定到第二个档案。
- 当前电脑的项目和应用可新增、编辑、打开。其他电脑的条目可查看来源，打开按钮禁用，并提示“请在该电脑上打开”。待绑定电脑显示绑定引导。
- 电脑列表显示“当前电脑 / 其他电脑 / 待绑定”状态及平台；可以重命名。解绑本机和删除电脑档案是不同操作，删除时要明确提示该电脑下的项目与应用入口将一起删除。
- 工作台记住上次选中的电脑与子栏目；当前电脑优先展示。

## 3. 数据归属

**文档**中的待办和速记属于用户的通用数据；**工作台**中的项目与应用入口属于某一台电脑。项目的本地目录、首选编辑器和应用的启动路径都随电脑保存。两台电脑即使添加了同名项目或同名应用，也各有一条入口和各自的路径。

建议的数据关系：

```text
ComputerProfile
  id: UUID                    # 同步时保持不变的电脑档案 ID
  name: string                # 用户可改的显示名称
  platform: windows|macos|linux
  created_at, updated_at, last_seen_at

LocalBinding                  # 仅存本机，不同步为可执行授权
  installation_id: UUID       # 此次应用安装的随机 ID
  computer_id: ComputerProfile.id

Launcher
  id: UUID                    # 稳定条目 ID，供未来同步使用
  computer_id: ComputerProfile.id # 必填；不能只依赖电脑名称
  kind: project|app           # 数据值从 software 迁移为 app
  name: string
  target: string              # 当前电脑上的项目目录或应用路径
  editor: string?             # 仅项目使用；也是当前电脑上的本地选择
  created_at, updated_at, deleted_at?
```

- 电脑档案 ID 使用随机 UUID，不使用电脑名、系统路径或硬件指纹做主键。改名、换磁盘、系统升级都不应改变档案身份。
- 项目与应用的去重范围是“电脑 + 类型 + 本地目标”；不同电脑允许相同目标文本或名称。
- 本机绑定凭据放在本地应用数据目录，云端电脑档案只描述归属。重装或清除应用数据后，允许用户重新绑定已有档案，避免凭电脑名自动猜测造成串号。
- 路径含有个人环境信息。未来同步可让用户选择是否同步完整路径；无论是否同步，其他电脑都不能直接运行这些路径。

## 4. 未来同步规则

1. 同一账号可拥有多台电脑档案。文档数据可以跨电脑同步；工作台入口按 `computer_id` 分组同步，互不覆盖。
2. 每台电脑默认只编辑自身的项目与应用入口。其他电脑的同步副本用于查看和备份，避免在错误的电脑上修改路径。
3. 打开项目或应用时，必须确认条目所属电脑与本机绑定的 `computer_id` 一致，并再次检查目标路径。同步下来的记录不能自动启动程序。
4. 同步采用稳定 ID、更新时间和删除标记，避免离线修改后复活已删除条目。具体冲突处理在同步功能开发时单独设计。
5. 若用户希望“同一个逻辑项目，在不同电脑上各有一个本地目录”，后续可增加跨电脑项目关联；首版先按电脑分别保存入口，不强行把同名项目合并。

## 5. 从当前版本迁移

目前 SQLite 的 `launchers` 表只有 `kind`、`target` 等字段，`kind` 为 `project` 或 `software`，唯一约束为 `(kind, target)`。实施本设计时：

1. 在一次数据库事务中创建当前电脑档案。
2. 为旧条目生成稳定 ID 并填入该电脑的 `computer_id`；将 `software` 映射为 `app`。
3. 将唯一约束改为 `(computer_id, kind, target)`，保留所有旧条目的名称、路径、编辑器和使用时间。
4. 将上次打开的“项目 / 软件”页面映射为“工作台 → 当前电脑 → 项目 / 应用”。
5. 迁移成功后再启用新界面；迁移失败时保留旧库并提示错误。

## 6. 本轮验收标准

- 主界面只有“文档、工作台、设置”三个顶层栏目；工作台下有“项目、应用”。
- 可以添加、重命名和查看电脑档案；当前电脑有清楚的标记。
- 旧版项目和软件数据升级后仍能在当前电脑下看到并启动。
- 新增项目或应用时自动归属当前电脑；另一台电脑的条目不能在本机启动。
- 两台电脑可有同名项目与应用，各自使用自己的路径。
- 暂不要求实现账号、云同步或跨设备远程打开。
