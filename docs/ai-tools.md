# AI 调用小助手功能

更新日期：2026-10-30。

AI 联系人支持通过注册的本机工具执行用户明确要求的操作。在联系人或会话权限中开启“允许操作小助手工具”。旧来源聊天仍保留输入框上方的“操作小助手”开关。自定义服务和模型需要支持 OpenAI 兼容 Chat Completions 的 `tools` / `tool_calls` 协议；Codex / Claude Code 通过每轮临时 MCP 连接获得获授权的工具。通讯录、群组、文件、命令和权限说明见 [AI 通讯录与协作](ai-collaboration.md)。

## 当前工具

| 工具名 | 功能 | 平台 |
| --- | --- | --- |
| `assistant_create_todo` | 创建待办，刷新列表 | 全平台 |
| `assistant_create_note` | 创建速记，刷新列表 | 全平台 |
| `assistant_create_reminder` | 指定延迟秒数或未来时间，创建提醒，可选择屏幕提醒 | 全平台 |
| `assistant_screenshot` | 打开原生截图框选界面 | Windows |
| `assistant_start_recording` | 打开原生录屏框选及倒计时 | Windows |
| `assistant_pause_recording` | 暂停当前录屏 | Windows |
| `assistant_resume_recording` | 继续当前录屏 | Windows |
| `assistant_stop_recording` | 停止录屏并等待视频封装，保留本地草稿供预览及保存 | Windows |
| `assistant_recording_status` | 查询录屏状态 | Windows |

例如：“新增待办：整理项目文档”“保存一条速记：今天完成了安装器优化”“十分钟后提醒我休息”“截图”“开始录屏”“暂停录屏”“停止录屏”。提醒支持相对延迟和毫秒级 Unix 时间戳，调用时附带当前本地时间供模型换算，Rust 再检查范围。

截图和录屏仍需用户在原生窗口框选。工具返回“等待框选”不代表截图完成或已经开始录制；后续原生完成、取消、失败和录屏开始事件会更新聊天中的操作记录。图片与视频不自动作为附件发送给模型；已有的本地 OCR / 自动译文仍遵循捕获设置。

macOS/Linux 当前没有这些原生捕获控制工具，模型不会收到不支持的工具定义，调用也会被拒绝。

## 分层与扩展接口

1. **工具注册**：`src-tauri/src/ai_tools.rs` 的 `Definition` 包含稳定工具名、显示名称、说明、对应功能开关、平台要求、JSON Schema 函数和 Rust 处理函数。
2. **模型编排**：`src-tauri/src/ai_agent.rs` 负责流式工具参数重组、完整性验证、按顺序执行、带调用 ID 回传结果，以及继续读取模型答复。它通过 `Host` 和 `Events` 接口工作，不依赖具体业务工具。
3. **界面与记录**：`src/ai-tool-state.ts` 管理通用操作记录、原生事件对账和展示。`src/ai.ts` 将记录保存进原会话，切换会话后仍更新原来的消息。

后续新增工具的步骤：

- 编写带 `#[serde(deny_unknown_fields)]` 的参数类型，验证类型、长度、范围及业务状态。
- 实现 `fn(&AppHandle, Value) -> Result<Value, String>` 处理函数，优先复用现有业务接口。
- 在 `registry()` 增加一条 `Definition`，提供 Schema、功能开关和平台条件；工具名保持稳定。
- 返回 JSON 业务结果；交互式操作返回 `state: "awaiting_user"` 及可关联的操作 ID，避免把“已打开”当成“已完成”。
- 数据变化后发出相应刷新事件；新的异步操作如需后续进度，应增加对应的通用事件对账。
- 为显示名称补充中、英、西翻译，添加参数、状态和失败路径测试。普通工具无需修改聊天页面的动作分支。

## 执行与重试约束

- 只向模型提供当前系统支持、且设置中已显示的功能；执行前再次检查。Rust 不提供任意命令执行、任意文件路径或网络操作接口。
- `ai_generate` 的工具开关默认关闭，只有普通聊天显式启用。模型连接测试、速记整理/提取待办、截图分析来源会话、OCR 翻译仍走原来的只读生成路径。
- 工具参数在完整流结束、工具结束原因及所有调用数据校验通过后执行；截断或错误 JSON 不触发工具。最多 5 次模型请求、12 次工具调用，每轮最多 8 个调用，按顺序执行。
- 数据写入、截图及录屏动作使用“会话 ID + 用户消息 ID + 工具名 + 参数”的本地执行记录。相同消息的同名同参数重试复用结果；新的用户消息可再次执行同样操作。
- 复用截图/录屏框选请求时会检查原生会话是否仍存在；已结束的会话显示结果待确认并引导查看原记录或草稿，不重新打开、不一直等待旧框选。
- 操作开始前先提交占位记录。程序异常退出导致结果不确定时，不自动重做该操作，同一轮其他写操作也等待确认；用户应检查对应列表或录屏状态。
- 停止生成取消后续模型请求和未分发操作，已经分发的本地操作可能完成，执行结果仍会记录。失败回复的操作记录保留，重试时作为上下文传给模型，防止误认为尚未执行。
- 删除会话或清空聊天时，同时清理关联的执行记录；已创建的待办、速记和提醒按原有规则保留。
- 服务拒绝工具请求时显示错误，用户可关闭“操作小助手”继续聊天；不会自动重发产生操作的请求。

## 验证

`npm test` 覆盖聊天开关、只读生成、操作记录转义及持久化、失败后重试上下文、原生事件竞态、切换会话及取消后的晚到结果。

`cargo test --offline --locked --manifest-path src-tauri/Cargo.toml --lib` 覆盖参数和时间校验、功能/平台过滤、幂等记录，以及本地 HTTP 模拟服务的真实多轮流式请求、工具结果关联、截断、不支持的工具、取消与调用上限。Windows 单元测试使用仅测试生效的链接指令声明 Common Controls v6；正式应用仍使用 Tauri 原有的清单与资源。

模型服务的工具协议参考 [OpenAI Function Calling](https://developers.openai.com/api/docs/guides/function-calling)。远端模型的实际指令理解与调用能力取决于所选服务；本地模拟服务用于验证协议和本机执行链路。

实机测试使用隔离的应用标识和数据目录，原有安装版及其数据保持独立。通过真实聊天界面和本地 HTTP 模拟模型，验证了待办/速记/提醒落库、回复失败后重试不重复创建、非法参数/未知工具拒绝、关闭开关后普通聊天、原生截图及录屏选区打开/取消后状态回传。录屏控制测试先用现有接口预置短录屏，再通过 AI 工具暂停、继续和停止，确认生成非空 MP4 草稿；测试没有模拟用户手动完成原生框选。请求检查确认没有自动附带图片和视频路径，删除会话同时清理执行记录。测试数据、草稿和临时模型配置已清理，隔离测试应用已退出。
