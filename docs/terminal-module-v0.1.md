# 终端模块设计 v0.1

- 日期：2026-10-30
- 状态：首版已实现本地终端、SSH、SFTP 与逐项确认的 AI 操作；本文件保留完整演进设计，实际交付范围见 [终端使用与实现范围](terminal.md)
- 范围：本地终端、SSH 连接、远程文件与传输、受控 AI 操作
- 技术基础：沿用 Tauri 2 + Rust + Web UI

## 1. 栏目名称与定位

建议新增一级栏目 **终端**。CMD 是 Windows 的一种命令解释器；终端栏目还需要容纳 PowerShell、其他系统的 Shell 和 SSH 会话，用「终端」更清楚。暂不另建「服务器」「文件传输」一级栏目。

二级侧栏管理多个会话，内容区以命令行为主。新建入口提供本地终端、SSH 连接、从已保存连接打开新会话。底部仅保留「终端设置」入口。

这里将「连接配置」「已连接会话」「AI 执行任务」区分开：同一台服务器可保存一份连接配置，同时打开多个会话，各自有终端状态和工作目录。AI 任务绑定具体会话和授权范围。

## 2. 页面布局

```text
一级导航       二级侧栏                 内容区
┌────────┬────────────────┬───────────────────────────────────┐
│ AI     │ 会话        ＋  │ 开发服务器 · 已连接   文件  AI  ⋯  │
│ 文档   │ 搜索会话/连接   ├───────────────────────────────────┤
│ 工作台 │ 本地            │                                   │
│ 终端   │  · PowerShell   │           终端输出与输入           │
│ 工具   │  · 项目调试     │                                   │
│        │ 远程            │                                   │
│        │  · 开发服务器   │                                   │
│        │  · 测试服务器   ├───────────────────────────────────┤
│ 设置   │ 终端设置        │ 当前目录 · 正在运行的任务/传输状态  │
└────────┴────────────────┴───────────────────────────────────┘
```

- 二级侧栏可折叠，会话支持命名、搜索、分组、关闭和状态标记。
- 顶部显示会话别名、连接状态和环境标记；生产环境有明确标识。
- 「文件」「AI」按需打开右侧面板，默认关闭，同一时刻只展开一个。
- 当前默认窗口为 880 × 620，不默认展开四列。文件面板可临时扩大到内容区；宽窗口再提供并排布局。
- 外壳、边框、按钮沿用现有样式，终端区域可切换浅/深色、字号、字体和行距。
- 一级栏目纳入现有功能显示及排序设置。显示开关与执行权限分别管理。

## 3. 本地终端

新建时填写名称、起始目录、Shell。Windows 默认提供可检测到的 PowerShell / CMD；macOS、Linux 使用系统可用 Shell。WSL 后续作为独立配置类型接入。

必须使用真正的 PTY，保留交互输入、颜色、光标、Ctrl+C、目录状态、全屏命令行程序与窗口尺寸调整。已有 AI 的单次命令执行工具不直接充当终端。

切换栏目不会结束会话；关闭会话与退出应用有明确的进程清理行为。重启恢复的是会话配置和列表，不自动重跑历史命令。关闭前展示仍在运行的任务状态。

## 4. SSH 连接

连接配置包含：名称、分组、主机、端口、用户名、认证方式、默认远程目录、环境标记、本机凭据引用，以及后续可选的跳板机/代理配置。

认证方式按阶段支持密码、密钥及 SSH Agent。默认连接普通账号；不自动提权。SSH Agent 使用与 Agent 转发是两回事，默认不向远程转发 Agent。[OpenSSH 对 Agent 转发的说明](https://man.openbsd.org/ssh_config#ForwardAgent)。

首次连接由用户核对服务器指纹，信任后保存到本机信任记录；指纹变化时阻止自动连接并要求处理。AI 不能替用户信任新主机或覆盖指纹。[OpenSSH 主机密钥校验](https://man.openbsd.org/ssh_config#StrictHostKeyChecking)。

区分连接中、等待用户认证、已连接、断开和连接失败。断线重连不自动重放命令。远端任务可能仍在运行，不能把本地断开或超时直接显示成「远端进程已终止」。长任务保活可在后续提供显式 tmux 方案。

客户端目标仍为 Windows、macOS、Linux。远程首版优先验证常见 Linux 服务器；Windows SSH 服务端的 Shell、路径及命令引用规则需要单独适配和测试。

## 5. 文件面板与传输

远程文件使用 SFTP，通过已认证的 SSH 连接打开独立通道。用户无需再次将密码交给文件面板。SFTP 在加密的 SSH 传输上完成文件操作。[OpenSSH SFTP 文档](https://man.openbsd.org/sftp)。

初步功能：

- 目录浏览、路径导航、刷新、排序与搜索当前目录。
- 拖拽或选择本地文件上传；下载时选择本地位置。
- 新建目录、重命名、复制路径、删除，以及受大小限制的文本预览。
- 传输队列显示方向、大小、进度、速度、结果，可取消。
- 同名覆盖明确确认；上传优先写入临时文件，完成后在服务器能力允许时重命名。
- 断点续传后续加入，续传前校验两端文件标识，不能仅按已有大小盲目追加。

常规窗口用「远程目录 + 本地文件选择器」，避免两份目录树挤占终端。复杂批量操作可扩大文件面板，后续再做本地/远程双栏视图。

人工文件操作和 AI 文件操作采用独立授权。AI 上传使用用户批准的文件引用和目标目录，不能因为用户打开了文件面板就获得整台电脑的读取权限。

## 6. AI 入口与操作方式

每个会话提供「AI 助手」入口，默认跟随设置中的主 AI，也可指定已有 AI 联系人。选择 AI 与授权服务器分别进行，不能把联系人原有的完全访问权限自动带入远程会话。

示例：

```text
检查这个服务为什么启动失败。
查看最近的错误日志，先给我修复方案。
把我选中的配置上传到这台测试服务器的 /srv/demo。
执行已确认的部署步骤，失败时停止并报告结果。
```

AI 面板展示计划、目标服务器、目录、待执行命令/文件操作和结果。可从已有 AI 群组把任务指向已授权的终端会话，任务编号与现有协作记录关联。

| 模式 | 可做什么 | 执行边界 |
| --- | --- | --- |
| 建议 | 解释选中输出、给出命令或步骤 | 默认不执行 |
| 受控诊断 | 读取授权目录、查看限定日志和状态 | 使用结构化工具，不提供任意 Shell 命令 |
| 确认后执行 | 运行用户确认的命令、上传或修改文件 | 审批绑定目标、目录和具体内容 |
| 本次授权自动执行 | 在已授权任务范围内推进多个步骤 | 明确的目标、期限、预算及执行能力；可随时撤销 |

任意 Shell 命令不能靠匹配 `ls`、`rm` 等关键词可靠区分只读与写入。因此「受控诊断」不直接开放任意命令；需要任意执行时使用明确确认或经过验证的系统级隔离。

默认通过独立执行通道运行 AI 命令，并在任务区展示，不向用户正在交互的终端盲目输入。AI 的目录、环境与交互终端可能不同，需要明确展示；后续可加入显式的「交给 AI 控制此会话 / 人工接管」模式。

一个明确计划可一键批准执行；新增步骤、改动命令或更换目标时重新判断授权。停止后保留实际结果，不自动回滚或重复执行已完成步骤。

## 7. 登录凭据不进入 AI 通道

核心流程：

```text
用户认证界面 ──→ Rust 凭据代理 ──→ SSH 认证和连接
                       │                 │
                       │            已连接的会话
                       │                 ▲
AI ──→ 会话编号 + 操作 ──→ 权限校验 ──────┘
               │
               └──→ 筛选/脱敏后的操作结果 ──→ AI
```

| 信息 | 保存/处理位置 | 给 AI 的内容 |
| --- | --- | --- |
| SSH 登录密码 | 本机系统凭据库及认证期间的后端内存 | 不提供 |
| 私钥、私钥口令 | 受保护的本机文件/凭据库/Agent | 不提供私钥内容或口令 |
| MFA、sudo 等敏感输入 | 专用认证交互，发送到对应后端通道 | 不提供输入内容 |
| 服务器配置 | SQLite 保存非秘密元数据与凭据引用 | 默认仅会话编号、别名和获准操作范围 |
| 执行结果 | 后端限量、过滤后返回 | 经授权的文本及执行状态 |

具体要求：

1. 由用户在本地完成认证，模型只请求使用已授权会话。AI 工具参数、聊天、提示词、日志、导出与未来同步中都不包含连接密码、私钥或口令。
2. 认证输入从专用界面投递到后端，避免作为普通终端键入内容进入记录。认证状态下暂停 AI 对该交互会话的控制，不把用户键盘输入流同步给 AI。
3. 密码不放进命令行参数、环境变量或脚本；不生成带密码的连接命令。优先支持密钥/Agent，但不能把 Agent 使用权当作没有风险。
4. AI 不能调用凭据读取接口。用于认证的凭据窗口与工具执行权限分开；任意页面脚本不能直接访问全部终端与密钥。
5. 终端、日志和文件可能含有 `.env`、Token、数据库口令等其他秘密。结果发送给模型前按范围读取、限量并脱敏；默认不实时上传整段终端，不自动附带文件内容。
6. 敏感文件采用明确的读取范围及后端规则。脱敏需考虑输出分块、控制字符与已知秘密匹配；单靠关键词或正则不能保证拦截编码后的任意秘密。
7. 不能把终端输出当作可信指令。远程日志和文件中的内容可能诱导 AI 读取或上传秘密，执行能力仍由后端授权判断。

**承诺边界：可以保证设计上的 SSH 认证凭据不经 AI 通道传输；不能在同时赋予 AI 同一系统账号下的任意命令、全盘读取或完全桌面控制时，承诺所有秘密绝对不可获取。** 系统凭据库也不等于同账号恶意程序无法读取。需要强保证的凭据模式，应使用经过验证的沙箱/独立安全主体隔离执行器和凭据代理，限制文件、网络与 IPC 权限。

首版 AI 建议优先接入自定义 API 模型，通过受控 Rust 工具操作已连接会话。Codex / Claude Code 可后续接入会话范围内的 MCP 工具；若 CLI 仍拥有任意本机命令权限，不能把它标为「凭据完全隔离」。当前项目的通用系统命令工具并不是 OS 沙箱，不能直接据此做强隔离承诺。

在本地终端中手工启动 `ssh`、`sudo` 或其他任意交互程序，不属于受管 SSH 认证流程。不能只靠识别 `Password:` 字样保证安全；此类会话启用 AI 时应限制读取和控制，或明确进入敏感输入模式。

## 8. 授权与执行记录

授权至少绑定：AI/联系人、任务或会话、目标连接、服务器指纹、远程账号、允许目录、操作类型、有效期。批准后变更任何关键目标信息，不沿用原审批。

- 默认每个新目标独立授权。生产环境标记后，通用命令执行默认要求确认。
- 文件浏览、读取、上传、覆盖、删除、命令执行、提权分别授权。
- `sudo` 或 MFA 由用户在专用交互中完成；AI 不持有密码，不默认配置广泛的免密提权。
- UI 展示实际命令、目录、退出码、已筛选输出、耗时及文件变化。一次授权可以撤销，连接断开或目标身份变化时使相关执行授权失效。
- 权限检查在 Rust 层完成，模型消息不能改变权限。命令来源、操作目标和当前连接都从可信任务数据取得。
- AI 执行任务使用现有的任务状态、取消和结果机制；远端执行不确定时标记「结果待确认」，禁止自动重试可能已经发生的修改。

## 9. 技术方案

| 部分 | 建议实现 |
| --- | --- |
| 界面 | 现有 Web UI；xterm.js 负责终端展示和交互 |
| 本地会话 | Rust + portable-pty，封装平台 PTY 与进程生命周期 |
| SSH | 优先验证 russh；预留系统 OpenSSH 适配器以覆盖已有配置或特殊环境 |
| 远程文件 | russh-sftp，复用 SSH 认证，文件传输流式处理 |
| 凭据 | 复用现有系统 keyring 能力；强隔离另设凭据代理边界 |
| 配置 | SQLite 存非秘密元数据、会话配方与授权记录 |
| AI | 复用现有 AI 执行器、任务、审批和 MCP 扩展机制 |

portable-pty 提供跨平台 PTY 接口，属于 WezTerm 项目；russh 与 russh-sftp 分别提供 SSH 和 SFTP 实现。最终依赖版本、认证方式、Windows Agent、跳板机及不同服务端的兼容性，要先通过原型验证。[portable-pty](https://docs.rs/portable-pty/latest/portable_pty/)、[russh](https://github.com/Eugeny/russh)、[russh-sftp](https://github.com/AspectUnk/russh-sftp)。

xterm.js 负责展示，不是执行或安全隔离边界。终端内容不可作为 HTML 注入；超链接、剪贴板控制序列及远程内容触发的浏览器行为需限制。终端 WebView 使用最少能力，AI 执行器与认证界面不共享任意系统访问能力。[xterm.js 安全说明](https://xtermjs.org/docs/guides/security/)、[Tauri 进程与权限边界](https://v2.tauri.app/concept/process-model/)。

## 10. 模块与数据

建议模块：`terminal_service`、`local_pty`、`ssh_transport`、`sftp_service`、`credential_broker`、`terminal_ai_tools`。统一后端接口，避免本地/远程各写一套页面和 AI 授权规则。

建议数据划分：

- `terminal_profiles`：连接配置、分组、环境与本机凭据引用。
- `terminal_sessions`：会话名称、所用配置、恢复所需的非秘密信息；真实进程/SSH 句柄只在运行时管理。
- `terminal_transfers`：传输记录、文件元数据、进度与校验点。
- `terminal_grants`：谁在什么目标、目录和时间范围内可执行哪些操作。
- `terminal_jobs`：计划、审批、操作状态与脱敏结果，关联现有 AI 任务。

人工终端写入通道与 AI 工具通道分别开放。AI 工具可包含 `terminal_exec`、`remote_list_files`、`remote_read_text`、`remote_upload` 等；参数使用受限会话/文件引用，不包含凭据，不提供 `get_password` 等接口。

未来同步时，本地 Shell 配置绑定电脑；服务器非秘密元数据可以选择同步，凭据与信任决定默认留在本机。另一台电脑首次使用时重新认证，不把登录密码混进普通同步包。

## 11. 性能方案

- 进入终端栏目时再加载终端组件；不因新增栏目增加常驻大依赖的初始化。
- 输出批量传输和绘制，避免每个字符触发整个应用渲染；使用有界缓冲、流量控制和有限回滚行数。
- 不可见终端暂停渲染；后台输出仍由有界缓冲管理，截断历史时给出提示，不静默假装完整。
- 文件直接在 Rust 中分块读写，不将大文件变成聊天附件或一次性塞入 WebView。
- 本地进程、SSH 读写、加密和文件传输不占用 UI 主线程。AI 并发沿用现有任务限制，并防止同一会话的命令互相打断。
- WebGL 加速可选，失败时回退默认渲染；不以第三方基准代替本应用的实测。

验收需覆盖多会话、连续日志、大文件传输、切换栏目、窗口缩放和后台占用，分别测量三平台表现。

## 12. 分阶段开发与验收

| 阶段 | 交付 |
| --- | --- |
| 1 | 终端一级栏目、会话二级列表、本地 PTY、多会话和基本设置 |
| 2 | SSH、凭据存取与认证隔离、主机指纹、SFTP 与传输队列 |
| 3 | 主 AI / 指定联系人、受控诊断、审批执行、取消与脱敏记录 |
| 4 | 跳板机、SSH 配置导入、WSL、续传、长任务保持与高级 CLI 接入 |

安全边界从第 1 阶段开始预留，远程 AI 执行应在认证隔离和主机信任验证完成后开放。

核心验收：

- 本地 Shell、尺寸变化、Unicode、交互程序和 Ctrl+C 正常；关闭及退出不会遗留本地子进程。
- 错误指纹不能静默信任，取消认证不会误连；文件面板与终端使用同一已验证身份。
- 密码、私钥和口令不出现在模型请求、操作参数、日志、导出与同步记录中。
- AI 无法通过受控工具读取凭据；不能通过改名、软链接或替换目标扩大已授权范围。
- 未批准的命令、上传、覆盖和提权不执行；拒绝/取消不影响用户原来的输入。
- 断线和不确定结果不自动重放；取消上传不把残缺文件显示为完成。
- 传输与输出持续运行时，主窗口、其他栏目和全局工具仍保持可操作。

以上为完整设计与验收目标，包含尚未实现的后续阶段；当前已交付项目与限制以 [终端使用与实现范围](terminal.md) 为准。
