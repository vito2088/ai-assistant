# AI 通讯录与协作

本次将 AI 栏目扩展为通讯录、私聊和群组。联系人既可以使用自定义模型 API，也可以调用本机的 Codex CLI、Claude Code。文件、命令和小助手工具在 Rust 后端执行，聊天区展示实际执行结果。

## 使用

1. 打开 AI，点击二级侧栏的 **＋ → 添加 AI 联系人**。
2. 自定义 AI：先在「设置 → AI 模型」保存模型服务，再在联系人中选择服务、填写模型 ID（可留空沿用该服务的默认模型）、角色和工作目录。模型必须支持 OpenAI Chat Completions 格式的工具调用；仅支持文本聊天的模型不能可靠执行工具。
3. Codex / Claude Code：选择接入类型，自动检测安装，也可指定绝对程序路径。左上角「＋」菜单的「本机 AI」中也可检测、安装或快速添加 Codex / Claude Code。点击「打开原程序」完成该 CLI 自己的登录或配置。本应用不读取或替换 CLI 的模型、密钥、订阅登录信息。无 API 密钥也能使用 CLI 联系人。
4. 点击联系人开始私聊；点击 **＋ → 新建群组** 选择 1～16 位 AI。群组可修改名称和成员，执行中需先停止任务再修改。
5. 在联系人或会话权限中选择工作目录和权限；会话设置只覆盖这个会话。空目录会使用应用数据目录内独立的 `agent-workspaces/<会话 ID>`，不会默认操作本应用的源代码目录。
6. 输入消息，Enter 发送，Shift+Enter 换行。可引用速记和图片；发送图片需要接收方为已开启图片能力的自定义 AI。CLI 可根据消息中的项目文件路径读取图片。

AI 二级侧栏底部仅保留「AI 设置」入口，可直达「设置 → AI 模型」。新建或编辑联系人时，「模型服务」选择框旁也提供同样的设置图标；跳转只打开模型设置列表，不叠加模型编辑弹窗。当前运行中已填写的联系人信息会保留，返回 AI 后继续填写，服务选项同步显示最新配置。

保存后的联系人固定绑定自己的服务与模型。切换「设置 → AI 模型」顶部的主 AI，只影响翻译、速记和截图等单模型功能，不会把群里所有 AI 一起切换。更换联系人的模型服务后，新的任务才采用新配置。

## 分工、等待与筛选

```text
@DS 先实现登录页，@GPT 等 DS 完成后检查修改并报告问题。
```

可以用名称或别名，例如 `DS 先实现…`。带 `@` 的写法更明确，输入时会显示成员提示。没有指定成员时，仅交给群组的默认负责人，不会向所有模型广播。同一条消息分别交给选中的成员，角色说明和任务依赖帮助成员理解自己的工作。

等待关系由本地规则识别，当前支持明确的一位执行者、一位等待者。也可以先给 DS 发任务，再发 `@GPT 等 DS 干完后检查`，此时复用 DS 最近一个可等待的任务。无法确定依赖时会提示补充，不会自行猜测创建任务。没有实现任意自然语言工作流或循环协商。

检查者只有在前置任务正常结束、结果保存成功后才启动，并收到该任务的结果。前置失败、停止、中断会阻断后续任务。正常结束表示执行器完成这一轮，并不自动证明代码正确或所有测试通过；检查者仍应读取实际文件并验证。

聊天顶部可勾选只看一个或多个成员，包括自己；点击消息上的姓名可以只看该成员。筛选只改变消息显示，任务依赖、运行状态和确认按钮保持有效。

## 权限

| 选项 | 自定义 AI | 本机 CLI |
| --- | --- | --- |
| 跟随原程序 | 不提供 | 不覆盖 CLI 原有权限配置 |
| 只读分析 | 只列举、搜索、读取授权目录；不提供文件写入或命令工具 | 向 CLI 传递只读/计划策略，最终受其自身实现和组织策略约束 |
| 项目内操作 | 读写项目与额外授权目录；编辑已有内容时校验原文 | Codex 使用 workspace-write；Claude 使用 acceptEdits |
| 完全访问 | 文件范围扩展至当前系统用户可以访问的位置 | 向 CLI 传递相应模式；关闭确认时允许其提供的跳过审批选项 |
| 允许执行系统命令 | 独立开关；当前用户权限、超时、真实退出码 | 使用 CLI 自己的命令机制 |
| 允许操作小助手工具 | 按当前栏目可见性提供工具 | 本轮通过临时 MCP 连接提供相同工具 |
| 桌面观察与控制 | Windows + 图片模型 + 完全访问 + 独立开关 | 当前联系人界面不开放此开关 |

自定义 AI 的写操作可以逐项确认；CLI 可以在启动任务前确认。CLI 通过 MCP 调用小助手的修改操作时，也需要经过小助手的确认设置。任务卡片中可展开查看具体操作，允许本次、拒绝或停止任务。

文件工具检查实际路径并阻止越界及符号链接逃逸。**系统命令不是操作系统沙箱**：一旦允许命令，程序本身可以访问当前系统用户有权访问的其他目录、网络等。Windows 原生 Claude Code 同样没有本应用提供的系统级命令沙箱。完全访问不会提权，也不能绕过系统或执行端的组织策略。

桌面工具可列举窗口、观察显示器、聚焦窗口、点击、输入文本和发送有限快捷键。点击需位于指定窗口客户区且未被其他窗口遮挡。观察会把截图发送给该联系人的图片模型，应在需要时单独开启；它与手动框选截图工具是两个入口。

## 可执行的工具

- 文件：列举目录、搜索文本、读取 UTF-8、创建目录、写入文件、精确替换。单个文件读取上限 128 KB；替换原文需唯一匹配，已有文件覆盖需提供读取过的原内容。
- 命令：在工作目录执行，返回 stdout、stderr、退出码，单次最长 120 秒；不用于启动长期驻留服务。
- 小助手：新增待办、速记、提醒；Windows 截图、开始/暂停/恢复/停止录屏、查询状态；列举并打开当前电脑的项目与应用入口。截图、开始录屏会等待用户完成框选，取消不会报告成功。
- 桌面：Windows 可选工具，结果图片从消息日志中移除；截图作为图片内容提供给当前视觉模型。

仅开启相应权限和功能时才提供工具。自定义模型能否正确选择工具，仍取决于该模型的工具调用与推理能力。

## CLI 安装与连接

检测覆盖 PATH、常见用户安装目录与手动指定路径。Windows 支持原生 exe、常见 npm cmd 入口及 ps1；常见 npm 包会直接调用其原生程序或 Node 入口，避免参数被 cmd 二次解析。提示词通过 stdin 传递。

安装按钮需要用户主动点击并确认：Codex 使用官方 npm 包，需要已有 Node/npm；Claude Code 使用官方安装脚本。安装检测只验证程序及版本，不能证明账号、计费或模型配置可用。登录仍在 CLI 原程序中完成。没有自动修改用户的认证配置，也没有在此次验证中实际安装软件。

CLI 采用非交互结构化输出，展示文本与执行活动，保留会话 ID。仅在联系人工作目录相同时恢复会话；更换目录会开始新的 CLI 会话。需要交互式审批的 CLI 操作可能被执行端拒绝，应查看任务错误并调整该联系人的设置，而不是默认开启完全访问。

临时 MCP 服务器由本应用自身的 `--ai-tool-bridge` 模式提供：stdio JSON-RPC 转发到本轮任务的回环端口，以随机凭据认证，只暴露获授权的小助手工具。连接配置仅用于这次进程，不改用户的全局 MCP 文件。结束或取消会关闭连接并清理临时文件。现有 CLI 配置或组织策略仍可能限制该连接。

## 数据、恢复与性能

- 联系人、会话、草稿、筛选、权限覆盖、任务和执行结果保存在本机 SQLite。API 密钥继续使用系统凭据存储。
- 旧普通聊天会导入通讯录会话；速记/截图来源助手保留原来的入口、内容和图片能力。
- 最多同时执行两个任务；同一联系人串行，已知相同工作目录的写入任务排队，完全访问任务与其他写入任务错开。额外目录和命令仍可能影响其他任务，应避免让多个联系人同时修改交叉目录。
- UI 按节奏刷新，默认只绘制最近一批消息，可加载更早消息；CLI 输出、日志、工具循环和文件搜索均有限额。
- 停止 CLI 时终止其进程树；停止 API 时取消后续模型请求和工具调度。已发生的文件修改不会自动撤销，系统命令已经产生的外部效果也无法回滚。
- 重启不会自动重跑未完成任务；已提交的结果用于恢复，未确认完成的任务标记中断。重新分配会创建新任务，需先检查实际修改。单轮内相同的小助手/文件修改请求有执行账本，避免重复副作用。
- 删除会话会删除任务与其工具执行记录；清空 AI 历史保留独立保存的速记、待办以及联系人配置。删除聊天不会删除项目文件。

聊天上下文、授权读取的内容、命令结果会提供给当前接入的模型服务。桌面图像仅在主动启用观察权限并调用观察工具时提供；普通截图工具不自动上传图像。CLI 使用它自己配置的模型、日志与数据策略。

## 扩展位置

| 文件 | 责任 |
| --- | --- |
| `src/ai-workspace-model.ts` | 联系人、会话、任务状态、点名与依赖规则 |
| `src/ai-workspace.ts` / `.css` | 聊天、通讯录、群组、权限、筛选、调度界面 |
| `src-tauri/src/ai_workspace.rs` | 持久化、可信任务绑定、审批、取消、结果与并发管理 |
| `src-tauri/src/ai_agent.rs` | 自定义 API 工具循环，独立 Host / Events 接口 |
| `src-tauri/src/ai_files.rs` | 文件范围、命令、小助手工具及权限适配 |
| `src-tauri/src/ai_cli.rs` | CLI 检测、进程、版本探测、结构化输出、会话恢复 |
| `src-tauri/src/ai_bridge.rs` | 每轮 CLI 的 MCP 工具桥接 |
| `src-tauri/src/ai_desktop.rs` | Windows 桌面观察与输入 |
| `src-tauri/src/ai_tools.rs` | 小助手工具注册表，见 [工具扩展说明](ai-tools.md) |

新增工具先定义 schema、权限和后端处理，再加入工具集合。新增执行端在联系人类型和后端 adapter 中接入，沿用同一任务、事件和审批协议，避免把权限判断写进模型提示词。

## 验证范围

自动检查包括前端调度、点名/等待、失败阻断、筛选、重启恢复、Rust 文件范围、真实子进程退出/取消、MCP 工具限制及协议解析。浏览器检查覆盖 800×560 与 520×420、中文/英文/西班牙文的群组、筛选、弹窗与确认操作。

Windows 独立应用数据目录的集成检查使用本地模拟模型和测试 CLI，实际执行文件编辑、系统命令、待办写入、依赖检查、原生桌面观察、测试窗口的聚焦/点击/键盘输入、CLI 会话恢复、MCP 创建待办与停止进程，不调用用户付费模型。前端 64 项与 Rust 62 项自动测试通过。真实模型质量、真实 CLI 账号/组织配置以及 macOS/Linux 的桌面控制没有由这些测试证明。桌面控制目前仅实现 Windows。
