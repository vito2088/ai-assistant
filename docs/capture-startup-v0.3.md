# 捕获启动优化 v0.3

更新日期：2026-10-29

后续窗口生命周期调整见 [常驻复用 v0.4](capture-startup-v0.4.md)；本页保留 v0.3 的实现与测量记录。

本轮针对 Windows 快捷键截图、录屏框选时的瞬间闪屏及启动等待，修改实际取屏与窗口显示链路。

## 取屏方式

过去截图与录屏选区的底图都通过一次 Windows Graphics Capture 会话获取，取到第一帧即停止。现在 Windows 的静态底图改用 GDI BitBlt 读取指定显示器，一次性复制到顶向下的 32 位 DIB；不为选区底图创建录制会话。真正开始视频录制后仍使用 Windows Graphics Capture 和 H.264 编码。

桌面缓冲转换为不透明 RGBA，并用快速、无损 PNG 编码生成临时底图；颜色通道与行顺序有编码解码测试。GDI 设备上下文、位图及原选中对象通过 RAII 释放。写入先落到临时文件再重命名，避免前端读到半份 PNG。

## 并行准备和首帧

- 需要隐藏助手时保留原状态恢复；Windows 取图前由 DwmFlush 等待合成器提交隐藏结果，移除隐藏主 WebView 中的 80 毫秒定时等待，避免后台限速放大停顿。
- 桌面底图与隐藏选区窗口并行准备，不再先等取图结束再创建 WebView。
- 主窗口不再接收一份用不到的完整 PNG 二进制；选区窗口只读取一次底图。
- 等待底图文件落盘放在原生工作线程，避免隐藏 WebView 的 JavaScript 定时器被降速。
- 选区窗口使用透明背景，图像解码、绘制完成后直接显示；移除隐藏窗口中的动画帧/定时器等待。
- Windows 选区及贴图窗口单独禁用 DWM 显隐过渡动画，不改系统全局动画设置。

## 保持的行为

对钩、Enter、Ctrl+C 复制并结束；保存按钮或 Ctrl+S 另存；贴图下方独立操作条；录屏先缩小窗口再绘制控制条。取消截图保留原来的主窗口隐藏/最小化状态。

macOS/Linux 继续使用已有系统选择器路径，本轮 GDI 改动仅在 Windows 编译。Windows 显示器使用原生坐标，包含非零及负坐标；GPU 特殊内容、HDR 等场景仍需要对应设备实测。

实现参考：[Microsoft 桌面图像捕获](https://learn.microsoft.com/en-us/windows/win32/gdi/capturing-an-image)、[BitBlt](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-bitblt)。未假定第三方截图软件的内部实现。

## 本机验证

- TypeScript/Vite 构建、Rust 检查及 PNG 通道、行序、透明度往返测试通过。
- 开发版在 3840 × 2160 显示器连续调用两次截图、一次录屏选区，分别使用新底图，图像完整、不透明且非空白；Esc 取消后主窗口保持最小化。
- 通过本机 WebView2 调试接口测得，从调用快捷键处理函数到选区可见约 920–990 毫秒，包含每次新建 WebView 的耗时；这不是发行版性能或与第三方软件的对比数据。
- 已验证首屏背景透明及显示时机；是否还有设备相关的瞬时闪屏，仍需实际屏幕观感确认。真正录制时的系统捕获边框保留。
