# 桌面待办小助手｜产品设计 v0.1

- 状态：讨论稿
- 日期：2026-10-23
- 范围：第一个功能“桌面待办”

## 1. 目标

让用户在桌面上随时看到待办，能快速新增、完成和管理事项；小组件可以拖到合适的位置，固定后不因误操作移动。关闭并重新启动应用后，待办、位置和固定状态仍然存在。

设计原则：打开即可用；新增待办的操作尽量短；日常查看时不遮挡太多桌面内容。

## 2. 首版使用场景

1. 用户打开小助手，桌面出现一个待办小组件。
2. 点击右上角“＋”，输入待办内容并按 Enter，事项立即出现在列表中。
3. 拖动组件的标题栏，将它放到桌面上合适的位置。
4. 点击图钉按钮固定位置；再次点击可解除固定并重新拖动。
5. 点击待办前的圆圈标记完成；已完成事项可以删除。
6. 下次打开应用时恢复之前的内容、位置和固定状态。

## 3. 界面草图

```text
┌──────────────────────────────┐
│ 待办                  📌  ＋  │  ← 标题栏可拖动
├──────────────────────────────┤
│ ○  回复邮件                  │
│ ○  整理周计划                │
│ ●  已完成的事项              │
└──────────────────────────────┘

点击“＋”后：
┌──────────────────────────────┐
│ 待办                  📌  ＋  │
├──────────────────────────────┤
│ 输入待办内容…         添加   │
│ ○  回复邮件                  │
│ ○  整理周计划                │

```

草图只表达信息结构，不限定最终视觉样式。建议首版采用小尺寸、清晰对比度和简洁控件；待办过多时列表内部滚动，组件不无限增高。

## 4. 交互规则

### 4.1 新增待办

- 点击“＋”后展开输入框并自动聚焦。
- 输入非空内容后，按 Enter 或点击“添加”保存；纯空格不能保存。
- 按 Esc 收起输入框；未保存的输入不进入待办列表。
- 保存成功后清空输入框并保持展开，方便连续添加。
- 单条内容首版限制为 200 个字符；超出时给出明确提示。

### 4.2 待办列表

- 新待办显示在未完成事项末尾。
- 点击圆圈切换完成状态；未完成事项在上，已完成事项在下。
- 悬停或通过事项菜单可删除单条待办，删除前提供可撤销入口，避免误删。
- 列表为空时显示“暂无待办，点击＋添加”。
- 首版不做截止日期、提醒、分类、同步和多人协作。

### 4.3 拖动与固定

- 只允许从标题栏的空白区域拖动组件；按钮、输入框和列表操作不会触发拖动。
- 拖动结束即保存位置。
- 点击图钉切换固定状态。固定后禁止拖动，并用图钉状态和简短提示反馈；仍可新增、完成和删除待办。
- 窗口移动到屏幕边缘时至少保留标题栏可见，以免组件难以找回。
- 屏幕分辨率或显示器布局变化后，若原位置不在可见区域，自动移回可见区域。

### 4.4 关闭与恢复

- 关闭应用后，下次打开恢复待办、完成状态、组件位置和固定状态。
- 数据默认保存在本机。首版不要求账号登录或云同步。
- 首次启动时显示空列表，并把组件放在主屏幕右侧的可见位置。

## 5. “驻留桌面”与“固定”的当前定义

为便于先推进设计，本稿暂定：

- **驻留桌面**：小组件独立显示在桌面工作区，系统正常运行时持续可见；其他应用窗口可能覆盖它。
- **固定**：锁定组件位置，不代表“始终置顶”。

这里有两个需要在开发前确认的产品选择：

1. 组件是附着在桌面、可被其他窗口覆盖，还是始终悬浮在所有窗口之上？
2. 固定只锁定位置，还是同时要求始终置顶？

上述定义是当前设计假设；确认后更新本节及验收标准。

## 6. 首版范围与验收标准

| 功能 | 验收标准 |
| --- | --- |
| 显示 | 启动后能在桌面看到待办组件；空列表有引导文案。 |
| 新增 | 点击“＋”后可输入并保存待办；空内容不能保存；连续新增不必反复点击“＋”。 |
| 完成 | 点击状态按钮可在未完成和已完成间切换，显示顺序正确。 |
| 删除 | 可删除指定事项，并能在短时间内撤销误删。 |
| 拖动 | 未固定时可从标题栏拖动，操作列表时不会误拖动。 |
| 固定 | 固定后无法拖动；再次点击可解除；图标状态清晰。 |
| 持久化 | 重启应用后，事项、完成状态、位置和固定状态全部恢复。 |
| 屏幕变化 | 调整分辨率或拔掉外接屏幕后，组件仍能找回。 |

## 7. 数据草案

```text
TodoItem
  id: 唯一标识
  text: 待办内容
  completed: 是否完成
  createdAt: 创建时间
  completedAt: 完成时间，可为空

WidgetSettings
  position: 屏幕位置
  isPinned: 是否固定
  windowSize: 组件尺寸（如首版允许调整）
```

本地存储需要避免异常退出时丢失已保存事项；具体存储格式随技术方案决定。

## 8. 实施顺序

1. 确认目标平台与桌面层级行为。
2. 实现组件外壳、拖动、固定和位置恢复。
3. 实现待办的新增、完成、删除与本地持久化。
4. 根据实际使用调整尺寸、视觉样式和快捷操作。

## 9. 后续迭代候选

- 截止日期、提醒与重复任务。
- 快捷键唤起输入框。
- 多个待办组件、分组或标签。
- 主题、透明度、字号与组件尺寸设置。
- 数据导入导出与跨设备同步。

这些是候选方向，不属于首版承诺。
