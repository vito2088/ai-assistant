# 捕获窗口常驻复用 v0.4

更新日期：2026-10-29

用户在 v0.3 后反馈：按下快捷键后、框选出现前，整个屏幕仍会闪一下。此前的 GDI 底图优化保留，本轮进一步修改捕获窗口的生命周期。

## 实现

- Windows 启动后预热一个透明、不激活的捕获 WebView；空闲时缩为 1 个物理像素，鼠标穿透、不可聚焦，不显示工具或图片。
- 使用 Tauri 的 `no_redirection_bitmap(true)`，绕过可能产生透明窗口首帧白闪的 Windows 重定向位图。捕获、录屏边框和贴图窗口都启用此选项，并明确设置透明背景。
- 截图、录屏选区复用同一个原生窗口和 WebView，不导航、不销毁，不反复切换系统可见性及捕获排除属性。
- 每次会话先清空前一张图、标注、选区、倒计时和工具状态。透明帧提交后才扩大窗口，底图绘制提交后才恢复鼠标交互和焦点，防止扩大窗口时拉伸上一帧。
- 取消、复制或录制完成后返回透明空闲状态，释放 ImageBitmap、完整尺寸画布及标注数组。保留一个 WebView 作为预热成本；OCR 如已使用可复用其已加载的工作线程。
- 进入交互前记住原来的前台窗口；退出时仅在焦点仍属于捕获窗口的情况下归还，避免透明空闲窗口占用键盘输入，也不打断用户已经切换到的其他窗口。
- 每次捕获生成独立会话 ID。并发请求被拒绝，旧会话延迟返回的图像或 ready 回调不能重新激活已关闭的捕获窗口。
- 捕获页先安装事件监听，再查询当前会话，覆盖预热尚未完成时立即按快捷键的情况。

底图与窗口准备仍并行进行。主窗口的隐藏/最小化恢复、截图标注、复制、保存、贴图，以及录屏倒计时和悬浮控制条沿用已有行为。

## 验证范围

Rust 状态测试覆盖并发请求拒绝、关闭后延迟 ready 回调失效、复用后旧 ID 无效。Windows 开发版另检查同一个窗口连续使用、透明空闲、鼠标穿透、模式切换和取消后的状态。构建和功能测试不能证明所有显卡、HDR 或全屏程序下都没有瞬时闪动，实际屏幕观感仍是最终依据。

Windows 本机回归已验证连续截图两次、真实区域录屏并停止、录屏后再次截图：全过程 HWND 和 WebView ID 不变，旧选区与工具状态不残留，取消后主窗口保持最小化，空闲窗口为透明的 1 × 1 像素并穿透鼠标、释放键盘焦点；录制得到有效的 MP4。调试版的这四次选区就绪时间为 753–965 毫秒，包含底图生成、解码与显示提交，不作为发行版性能保证。

常驻复用仅用于 Windows。macOS/Linux 继续使用原有系统选屏及捕获后关闭窗口的方式，本机未进行这两个平台的实测。

实现参考：[Tauri 透明窗口与 no_redirection_bitmap](https://docs.rs/tauri/latest/tauri/webview/struct.WebviewWindowBuilder.html#method.no_redirection_bitmap)、[Windows 捕获排除属性](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity)。未假定微信截图的内部实现。
