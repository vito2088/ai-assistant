# 桌面小助手｜产品总览 v0.8

- 状态：当前实现方案；本地工作台已开发，未来同步见[工作台模块设计](workbench-module-v0.1.md)，开发进度见[开发状态](implementation-status-v0.1.md)
- 日期：2026-10-23
- 平台目标：Windows、macOS、Linux 桌面系统（暂按这三种系统理解）

## 1. 产品定位

桌面小助手是一个可持续增加功能的本地应用。用户可以将常用入口留在桌面，需要时快速展开操作。文档（待办、速记）和按电脑归属的项目、应用入口都通过统一入口访问。

当前规划：

| 功能 | 用途 | 详细设计 |
| --- | --- | --- |
| 文档 | 包含待办与速记两个子栏目；记录任务和临时文字 | [文档模块 v0.1](document-module-v0.1.md) |
| 工作台 | 管理电脑档案；每台电脑下保存自己的项目与应用入口 | [工作台模块 v0.1](workbench-module-v0.1.md) |
| 工作台 → 项目 | 保存当前电脑的项目文件夹与首选编辑器，点击即可打开 | [项目管理 v0.1](project-manager-v0.1.md) |
| 工作台 → 应用 | 保存当前电脑的常用应用入口，点击即可启动 | [软件管理 v0.1](software-manager-v0.1.md) |
| 工具 | 小图标入口：计算器、截图、录屏；支持桌面框选标注、区域录屏、完成后保存与本机草稿 | [工具增强 v0.2](tools-module-v0.2.md) |

## 2. 应用层级

```text
桌面小图标 / 主窗口入口
          │
          ▼
       小助手主界面
       ├─ 文档
       │  ├─ 待办
       │  └─ 速记
       ├─ 工作台
       │  ├─ 电脑档案 / ＋ 添加电脑
       │  └─ 所选电脑
       │     ├─ 项目
       │     └─ 应用
       ├─ 工具
       │  ├─ 计算器（图标）
       │  ├─ 截图（图标）
       │  └─ 录屏（图标）
       └─ 设置
```

- 小图标是小助手的统一桌面入口，不只代表待办。
- 展开后主界面提供“文档”“工作台”“工具”“设置”四个入口或标签，记住上次访问的大栏目。文档内部记住上次打开的“待办 / 速记”；工作台内部记住上次选中的电脑及“项目 / 应用”。工具使用小图标入口，不使用子标签栏。
- 待办的紧凑列表属于待办功能的专属显示方式。项目和应用首版在工作台中使用。
- 小图标悬停时，保留“展开、新增待办、固定、紧凑列表”等快捷操作；项目和应用通过展开主界面进入。
- “固定”是小助手窗口层面的行为：锁定位置并在普通应用窗口上方显示；切换到工作台时同样有效。
- “最小化”将小助手窗口最小化到系统任务栏，点击任务栏图标可恢复；托盘菜单也可显示窗口。

## 3. 主界面草图

```text
┌──────────────────────────────────────┐
│ 小助手                  📌   −   ○  │
├──────────────────────────────────────┤
│ [文档]   [工作台]   [工具]   [设置]   │
```

主界面可拖动、收起为小图标，固定与最小化遵循统一规则。待办旧设计稿中的“展开列表”在本版产品结构里对应“文档 → 待办”；详细交互见[待办设计 v0.4](desktop-todo-v0.4.md)。工作台交互与数据归属见[工作台模块 v0.1](workbench-module-v0.1.md)。

## 4. 跨功能规则

- 待办、速记作为用户文档保存；项目与应用入口按电脑档案归属，目前仍在本机持久保存。
- 主界面切换功能时，不清空未完成的数据操作；若编辑表单已有未保存内容，应提示保存或放弃。
- 项目快捷打开属于本地应用启动操作；启动失败时在小助手中给出错误原因和修复入口。
- 应用快捷启动也需要明确的点击动作；启动失败时提示原因和编辑入口。
- 仅当前电脑可打开其所属项目和应用；其他电脑的条目只能查看，不能在本机启动。
- 首版不要求登录、云同步或跨设备共享。
- 同一功能在各系统尽量保持相同的操作流程；项目路径、可启动软件入口与窗口层级由各系统适配。
- 设计稿中的 `D:\...` 仅是 Windows 路径示例；macOS 与 Linux 使用各自的本地路径。

## 6. 开机启动设置（2026-10-23 补充）

- 设置页提供“开机启动”开关，默认关闭。
- 开关读取操作系统中的真实注册状态；开启和关闭后立即更新。
- 注册失败时提示原因并恢复开关状态，避免界面显示与系统状态不一致。
- 开机启动后恢复上一次显示状态和本地数据；最小化与退出仍保持不同语义。

## 7. 待确认

- 平台范围暂按 Windows、macOS、Linux；最低系统版本和 Linux 桌面环境待确定。
- 小图标悬停入口较多时，是否改为可展开菜单，需要通过原型验证。
- 最小化后保留系统任务栏入口，同时提供托盘菜单恢复；macOS、Linux 对应系统入口与托盘交互待验证。
- Linux Wayland 对全局窗口位置和普通置顶 API 有限制；“固定位置并始终置顶”在该环境下不能直接承诺与 Windows 完全一致，需原型验证并设计降级提示。
